# 从一个新系统做到成片

## 1. 从业务问题写大纲

先拿到观众、要解释的决定、时长、系统入口或录屏、业务口径和配音要求。观看可打开的参考成片，记录「镜头在哪一刻动、动向哪里、结果停多久」。如果只拿到封面或链接无法播放，注明可核对的部分。

用同一结构写每段。谁在什么情况下遇到问题？系统依据什么做了哪一步？观众能在哪个字段看到结果？这个结果交给谁？交给业务同事审核的是段落顺序、旁白、对应的真实操作和预估时间。确认后按自然语速试读，超时优先删话。

### 这次选址片怎样落到画面

| 选址团队的问题 | 智能体负责的工作 | 镜头要证明什么 |
| --- | --- | --- |
| 手里有一块地，值得去建吗？ | 单站评估智能体汇总重卡车流、停车和竞站情况，对照现场踏勘，把建议和待核风险写入报告。 | 打开同一个候选站，从周边证据看到报告内的风险项。团队知道下次踏勘该核实什么。 |
| 只有一条线路，从哪里开始找地？ | 线路选址智能体沿线比较路段画像，筛出适合的路段，在附近匹配候选地块。 | **选线路 → 筛路段 → 点开某一路段 → 打开与它匹配的地块**。路线编号、路段名和地块边界接得上，观众能看出推荐如何缩小了找地范围。 |
| 多条线都值得建，全省先建哪里？ | 网络布局智能体统筹路网覆盖及站间距，给出布局方案和建设优先级。 | 由局部地块拉回全网，再点「优先」，让地图和清单的真实变化同时进入视野。 |

三段按不同业务问题组织。开头直接进系统，数字用来证明判断，单个城市和地块放在对应操作中。更换系统时重新设计业务链。例如设备派单可以用「待派工单 → 指派班组 → 回到队列核对状态」，让观众看到协调员原本要逐个通知的工作如何完成。

## 2. 录屏和取景

复制[镜头清单](../assets/镜头清单.csv)。取景前写好每镜的对象、点击目标和可见结果。用浏览器、系统录屏或 Playwright 在已授权的演示环境操作。先录最难讲清的一条链，小范围验证后再录全片。需要练手时，打开随包的[设备工单练习页面](../assets/练习系统.html)，点击「查看工单」「派给机修一组」，刷新可复位。

- 清除通知和无关标签，用演示账号及可展示的数据，按交付画幅录原屏。1080p 交付时优先用至少 1920×1080 的清晰源；需要推近局部，先在系统内适度放大或补录详情。保留原始文件，避免把聊天软件压缩后的副本再放大。
- 光标停到目标后再点；让筛选条件、加载完成的数量和结果有机会同时出现。保存素材入出点。把无意义的等待剪短，保留选中、更新、定位、展开和落稳的顺序。动作难以辨认时先改取景和停留时间。
- 更换记录或版本时保留足以辨认的页面标识。敏感内容使用演示数据或在录制前处理。给屏幕密集的结果一次正常速度的阅读机会，再转下一镜。

## 3. 用同一位讲述者配音

先读一句产品名、一句数字和一句跨段衔接。确认音色、读法和速度，再录整段。语气像带同事看系统，把重音放在动作和结果上。真人录制时保持同一房间、麦克风和距离；合成时固定声音、模型版本、参考样音及对应原文，保存设置。用审批通过的整段 WAV 作为主旁白。

模板随附本次选址片的女声参考音、对应原文和固定生成设置。复制工程后把新稿写入 `配音/旁白.txt`，在 M 系列 Mac 上运行 `配音/生成女声.command`。生成成功后 `public/audio/旁白.wav` 自动更新，Studio 的「团队女声」轨已指向该文件。按新声音的实际时长调整画面和字幕。详见[配音使用说明](../assets/remotion/配音/使用说明.md)。

重录一句时，连同前后各一句录一条，在自然停顿处拼接并试听两侧。换章处音色、气息或节奏明显跳变，就用同一设置重录整段。字幕对照最终声音校时，数字、地名、型号再对页面核一遍。

## 4. 在 Remotion Studio 合成

按[团队接片指南](团队接片.md)打开工程。先放主旁白，再排真实动作，让说出结果时观众已经看到对应字段。配乐和操作音独立控制，给真正的点击、结果出现和关键转场配声，试听人声能否轻松听清。用[页面转场工作流](页面转场工作流.md)把上一镜的对象带入下一镜。按近景、局部、全局改变观看尺度，同时保留界面辨识度。

## 5. 正常速度复看，交付可接手的工程

| 怎么看 | 要回答的问题 | 有问题时怎么改 |
| --- | --- | --- |
| 静音，关闭口播字幕 | 第一次看的人能指出「选了什么、系统改变了什么、最终得到什么」吗？ | 重录断掉的中间动作，调整裁切或延长结果停留。 |
| 单独听旁白，跨过每处换章 | 像同一位同事自然讲产品吗？数字读对了吗？ | 补录时带上下文，对齐呼吸和音量，重新核字幕。 |
| 播放完整导出文件 | 系统字清楚吗？声音压过讲解吗？结果能读完吗？ | 回到对应镜头修正，再检查受影响的前后镜。 |

有第二位同事时，请他在静音后复述业务链。把实际看过和听过的检查写在交付说明里。技术核验用 Python 3、FFmpeg 和 ffprobe，按项目画幅、帧率和片长调用验片脚本；示例见接片指南。最后从独立解压目录打开 Studio，改一镜、导出，验证工程没有引用制作者电脑上的路径。
