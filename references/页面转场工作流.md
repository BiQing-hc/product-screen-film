# 从一个真实操作接到下一个

先在前后画面各指出一个位置。观众刚看了什么？下一镜要在哪里找到同一个对象或它产生的结果？界面本身的筛选、缩放或边栏展开已经能交代这层关系时，保留真实操作。

| 页面关系 | 可复用的动作 | 怎么落到产品上 |
| --- | --- | --- |
| 同一对象，从列表或缩略图进入详情 | `match-iris` 圆形展开 | 从已选中的工单打开该工单的处理区。从站点档案打开踏勘边界时沿用同一地块。 |
| 从局部看全局 | `map-pullback` 拉远 | 从候选地块拉回所属路段，再到全省网络，把新视野的关注处留在画面里。距离及边界以真实地图为准。 |
| 从已有判断进入下一步 | `sheet-lift` 叠页推入 | 从计算结果到报告正文，沿阅读方向推入。等结果落稳再读正文。 |

## 在 Studio 试动作

打开模板，选择 **PageTransitionDemo**。它用虚构的工单练习系统的真实操作截图演示三个动作。逐帧看动作起点、中段及结束帧。三组配置在 [demo.json](../assets/remotion/demo.json)，前后图片在同一模板的 `public/`。在工程目录运行 `npm run render:transitions`，会导出 `out/page-transitions.mp4`。运行 `npm run check:cuts` 可校验随包练习时间表的锚点、越界和重叠。

## 把动作加进实际成片

1. 连续录下操作前、点击和结果，确保两端来自同一业务链。镜内筛选和匹配地块先让系统自己演完。
2. 在 `ProductFilm` 的右侧 Inspector 切到 Default Props 的 JSON 视图，找到切入的后一镜，给它添加下面的 `transition` 字段。模板会定格前一镜的最后一帧，同时播放新镜的真实录屏。动画占用后一镜开头，所填帧数要小于该镜长度，因此给结果单独留下阅读时间。
3. `source` 和 `target` 分别是前后对象在完整成片画幅内的位置，横纵坐标均为 0 到 1。先从原系统页面定位对象；只掌握大致方位时，用普通切换或叠页，避免让动画暗示精确地理对应。
4. 在正常速度复看。地图清楚才开始说路段，地块边界停稳才讲建议。旁白保持连续，操作音独立放在真实动作处。

```json
"transition": {
  "effect": "map-pullback",
  "frames": 22,
  "source": [0.48, 0.53],
  "target": [0.58, 0.64]
}
```

上面是镜头对象中的一个字段。圆形展开也可设置两个位置。叠页可用 `{"effect":"sheet-lift","axis":"y","frames":18}`。`frames` 是 30 fps 下的帧数，可以按两个页面的实际变化调整。

复用的 [PageTransition.tsx](../assets/remotion/PageTransition.tsx) 包含三种动作。圆形遮罩和叠页来自 Video Shotcraft 的 CircleMatchIris 与 BottomPushStackWipe，本工程保留 [Apache-2.0 许可](../assets/remotion/LICENSE-Video-Shotcraft) 和源码归属。[Video Shotcraft 固定源码版本](https://github.com/Vincentwei1021/video-shotcraft/tree/075b548c2405a07b77129eb448b0b504fc60dea3)
