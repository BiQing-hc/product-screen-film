# 第一次使用和接手改片

## 第一次安装

1. 从团队拿到 `product-screen-film.zip` 并解压，或用有仓库读取权限的 GitHub 账号打开 [product-screen-film](https://github.com/BiQing-hc/product-screen-film)，选择 **Code → Download ZIP** 后解压。
2. 把包含 `SKILL.md`、`assets`、`references`、`scripts` 和 `agents` 的整个文件夹放进新系统项目的 `.agents/skills/`，文件夹名改为 `product-screen-film`。从 GitHub 下载时去掉文件夹名末尾的 `-main`。最终入口是 `.agents/skills/product-screen-film/SKILL.md`。团队项目已包含这个目录时可以直接使用。
3. 用 Codex 打开**该项目根目录**，新开对话，输入 `$product-screen-film` 和任务。填上系统入口、资料目录、观众、重点、片长及旁白要求。系统需要登录时，由有权限的同事打开演示环境或提供可用的录屏。

**可以直接复制给 Codex**

> 请用 $product-screen-film 为设备运维系统做一条 60 秒宣传片，给调度负责人看。系统入口在【地址】，可展示的工单在【资料目录】。重点讲清从发现故障、派给班组到核对处理结果，先给大纲和真实操作分镜，等我确认后再录。全片用同一位女声，在 Remotion Studio 做成可接手的工程。

## 打开工作台

新系统从 Skill 里**复制** `assets/remotion` 整个目录到自己的制作目录，例如 `设备运维宣传片/`。把录屏、旁白、音乐和提示音放在这份工程的 `public/`。用装有 Node.js、npm 的电脑，在复制出来的工程目录运行：

```sh
npm ci
npm run check
npm run studio
```

打开终端显示的本机地址，左侧选择 **ProductFilm**。默认是 5.4 秒的设备派单练习，可在时间线上找到「打开待派工单」「派给班组并核对结果」和两个操作音。想比较三种转场，选择同一个工作台里的 **PageTransitionDemo**。跟业务同事一起录一遍时可打开 [练习系统](../assets/练习系统.html)。

## 把练习换成自己的系统

| 想换什么 | 去哪里改 | 改完看哪里 |
| --- | --- | --- |
| 真实录屏、取哪一段 | 把源文件放在 `public/`。在 Studio 右侧的 `shots` 中按讲述顺序填写 `id/name/file/trimBefore/frames`。例如 `file` 写 `clips/派单.mp4`，对应 `public/clips/派单.mp4`。 | `trimBefore` 是源片入点，`frames` 是成片中保留的长度。模板每秒 30 帧，30 帧等于 1 秒。素材必须足够长。 |
| 旁白、BGM、操作音 | 在同一面板的 `audio` 中各建一项，分别用 `narration`、`music`、`sfx`。填相对文件名、全片开始帧 `from`、持续帧数和音量 `volume`（0 到 1）。用一个纯人声文件贯穿全片。 | Studio 的右栏 可分别切换 `narration/music/sfx`。源录屏默认静音，避免录屏中的人声与主旁白叠加。 |
| 字幕和停留时间 | 每镜 `captions` 使用该镜内的开始帧 `from`、时长 `frames` 及 `text`，填写实际听到的话。 | 将播放头拖到开始和结束附近，试听事实、数字和句尾。右栏中可关闭 `captions` 复看业务动作。 |
| 镜间动效 | 相邻录屏原本连续时保留原动作；需要跨页时，在**后一镜**填写 `transition`，见[转场手册](页面转场工作流.md)。 | 从前一镜最后一次点击看到新镜结果落稳，确认转场保留了结果的阅读时间。 |

比如在一条恰好 60 秒、30 fps 的片子里，纯旁白轨可以这样写。将这项放入 `audio` 数组，用实际 WAV 的开始位置和长度替换示例值。

```json
{"name":"全片女声","kind":"narration","file":"audio/旁白.wav","from":0,"frames":1800,"volume":1}
```

在 Studio 选择 **ProductFilm**。用 **View → Right Sidebar → Expanded** 打开右栏，进入 **Inspector → Default Props → Schema**。展开 `shots` 或 `audio`，可直接改长度、字幕、录屏文件名或音量。也可切到 **JSON** 编辑整段参数。使用 Schema 修改字段后按 Tab 或点到下一项，Studio 会将修改写回工程的 `src/Root.tsx`。重新打开后再核对一次。镜头长度改变时，该镜之后的画面会自动顺延，全片音轨的入点与旁白节奏需一起复核。

## 只改一个镜头

> 请用 $product-screen-film 打开【工程目录】。把「派给班组」里已派单的结果多留 1 秒，保留原女声。只调整该镜和受影响的字幕、音效对齐，先在 Studio 给我看前后两镜，再导出。

先按镜头名称和时间码定位。若源录屏有后续动作，要延长稳定结果，可补录停稳画面或用结果帧定格。只换画面时保留原人声文件。改了台词时用同一讲述者补录，连听前后句，再按新的 WAV 校字幕。最终时长有硬性要求时，从其他可缩短的等待处找回所需时间。

## 导出和交接

命令行导出使用 FFmpeg 和 ffprobe 将声音精确收在最后一帧。先安装这两个工具，并确认能在终端运行。

```sh
npm run check
npm run render
```

新模板输出 `out/product-film.mp4`。随工程交付源代码和锁文件、`public/` 全部被引用的素材、最终脚本与镜头表、字幕以及旁白配置说明。依赖可以通过 `npm ci` 重建。把使用过的素材许可一并交付。换电脑或换目录验证时，打开复制的工程，改一镜并重新导出。

需要技术验片时，把 Skill 的 `scripts/check_film.py` 复制到工程根目录。在装有 Python 3、FFmpeg 和 ffprobe 的机器运行。下面的 5.4 是练习片的时长，正式项目换成约定秒数。已有实填镜头表时追加 `--shots 镜头清单.csv` 逐镜抽帧；每次指定新的结果目录。

```sh
python3 check_film.py out/product-film.mp4 --duration 5.4 --out 检查结果
```

## 已拿到大象超充 90 秒工程

解压内部交付的《大象超充-智能选址90秒-可编辑工程.zip》，在工程根目录运行同样的安装、检查、Studio 命令，选择 **EVCS**。在 `制作/镜头表.csv` 查时间，修改 `src/shots.json` 对应镜头或取景，`src/captions.json` 对应字幕，`public/media/` 对应源画面。配音用 `制作/大象超充-女声配音包.zip`，详见[配音方法](制作手册.md#3-用同一位讲述者配音)。最终成片由 `npm run render` 导出为 `out/EVCS.mp4`。客户工程和音色样音由项目负责人按需提供。
